# QABB Dataset — Processing Outputs

Repeat of the MCA/PwM archive pipeline for the **QABB** dataset (Queen Alexandra's
Birdwing / *Ornithoptera alexandrae*). Kept fully separate from the PwM work; every
output is prefixed `QABB_`. The PwM folders were not touched.

## Source
Google Drive **"Qabb docs"** (`1srfEvNDu6QK9Am3dbMAwNrWZubFhovLG`), two subfolders,
recursed in full (the `__MACOSX` / `.DS_Store` zip-junk was skipped):

```
QABB reference material CI OPRA
  └─ QABB Ornithoptera alexandrae
       ├─ 1_QABB_Ornale   ├─ 2_Pararistolochia   ├─ 3_General   └─ 4_File 2-6-1 Correspondence
  └─ Other material
QABB references from Christine and David Mitchell
```

**152 documents** (146 PDF, 3 .doc, 2 .docx, 1 .xlsx) + **47 images** (~1.3 GB).

## Destination (created under "MCA Document archive")
- **`QABB Indexed Documents`** — mirrored subfolder tree; all 152 source documents
  placed via server-side `copy_file`. (`1CUOsnLxG5iJjhsFcHw0qAmq1ZkTG6yD4`)
- **`QABB Indexed Images/Images`** — all 47 images consolidated under systematic
  filing names `QABB_<Prefix>_<NNN>` (`Ornale` 001–031, `Parari` 001–009,
  `General` 001–007). (`1ZV18LjGkngWfliDltaGzlgEuxqRWY8Bt`)

## Pipeline as run
1. **Enumerate** — one OR-query across every content folder (snippets on) auto-saved
   to disk; parsed there, never pulled into context.
2. **Full text** — extracted for all 152 docs (Google Drive `read_file_content`),
   feeding the index and dedup. 135 have a real text layer; 17 are scanned with none.
3. **De-duplicate** — same-filename match (catches the scanned volumes that carry no
   text, which pure Jaccard misses) **plus** 5-gram-shingle Jaccard on the text.
   The 5 Orsak volumes each appear twice (CI OPRA set **and** the Mitchell set); the
   smaller text-searchable copy of each is kept, the redundant copy is excluded from
   the index and listed in `QABB_duplicates_to_delete.csv`. Three further pairs are
   near-identical but look like **distinct records** (a 2001 proposal vs a 2002 draft,
   etc.) — kept and cross-linked as "related", not removed.
4. **Images** — consolidated + filing-named; tagging tool generated.
5. **Index** — full-text, links repointed to the shared destination copies (147/147
   file-format links; 1:1, no name collisions).

## Two environment constraints (important)
1. **No delete/trash tool** in the Drive MCP — files can be copied in but not removed.
   So dedup is applied *logically* (the redundant copies are excluded from the index);
   delete the 5 files in `QABB_duplicates_to_delete.csv` from Drive by hand (one click
   each) to physically remove them.
2. **No practical way to upload generated bytes** — `create_file` only takes content
   inline through the model context, which is unworkable for real PDFs (and impossible
   for the 101 MB manuscript). Consequences:
   - Office docs are placed in the archive as their **originals** (`.doc/.docx/.xlsx`);
     three were also converted to PDF locally (in `converted_office_pdfs/`) but could
     not be uploaded.
   - The 14–17 **scanned, text-less** volumes (e.g. the 340 MB Orsak Vol 2, Meek 1913)
     are flagged in the index as "scanned — OCR pending". Rotating/OCR'ing them locally
     is possible, but the improved file can't be written back to Drive here. They remain
     fully browsable as the original scans; they are just not full-text searchable.

## Scanned documents — OCR (DONE)
The 14 scanned / no-text files were OCR'd in the user's own Drive via
**`QABB_OCR_scanned_docs.ipynb`** (Google Colab) — the bytes can't leave this session
(the MCP download tool only returns base64 through the model context, too large for even
a 1 MB PDF, and direct `drive.google.com` egress is blocked by policy), so OCR ran where
the bytes already live. The notebook OCR'd all 14 (13 scanned PDFs + the 106 MB
manuscript `.docx`, converted to PDF first), `eng+fra`, rotate + deskew, into a
**`QABB OCR output`** Drive folder (`_OCR.pdf` suffix — nothing overwritten), and emitted
**`QABB_ocr_results.csv`** (original id → OCR'd id).

Those results are now folded into the index (`ocr_results.csv` in the working set):
- **12 of 14** formerly-scanned documents are now **full-text searchable** in
  `QABB_document_index.html`, and their entries link to the searchable `_OCR.pdf` copy.
- **2 of 14** — `Meek_1913_Naturalist.pdf` and `O_alexandrae_MANUSCRIPT` (each ~106 MB) —
  were OCR'd successfully (text layer embedded, so the **PDF itself is searchable** when
  opened), but are too large for the `read_file_content` tool to extract inline, so they
  are flagged **"OCR complete — searchable inside the PDF"** rather than indexed inline.
- `Blandin_1973_Fr.pdf` (French) additionally has an English translation:
  **`Blandin_1973_translation_EN.md`**.

The OCR'd copies live in a separate **`QABB OCR output`** Drive folder; the index links
there. Moving/renaming them into `QABB Indexed Documents` (to replace the scans) is a
manual step in Drive if desired — same delete/move limitation as the duplicates.

## Known limitation
A few small PDFs (e.g. `Sullivan_circa_1999_Managalas.pdf`) extract with fragmented
letter-spacing from the Drive text tool; their filename/keywords are searchable but
in-document full-text is degraded for those specific files.
